# MP3 자동 채보 로직

Neon Velocity의 MP3 변환은 서버나 외부 AI API 없이 로컬 파형만 분석합니다. 브라우저에서는 `AudioContext.decodeAudioData`, 명령줄에서는 FFmpeg로 음원을 PCM 샘플로 만든 뒤, 두 경로 모두 `src/audio-chart-generator.js`의 같은 알고리즘을 사용합니다.

## 전체 흐름

```text
MP3
  → PCM 디코딩
  → 저·중·고역 에너지 추출
  → 에너지 상승량(onset flux) 계산
  → 자기상관으로 BPM 추정
  → 비트 그리드 위치 보정
  → 강한 타격 후보 선택
  → 난이도별 밀도 제한
  → 주파수 대역을 4개 레인에 배치
  → 채보 JSON 생성
```

## 1. MP3 디코딩

- 브라우저: 사용자가 선택한 파일을 `AudioBuffer`로 디코딩합니다.
- 명령줄: FFmpeg가 입력을 44,100Hz, 모노, 32비트 부동소수점 PCM으로 변환합니다.
- 이후 알고리즘은 `sampleRate`, `length`, `duration`, `getChannelData()`만 사용하므로 두 실행 환경의 결과 구조가 같습니다.

## 2. 에너지 대역 분리

512샘플 단위로 파형을 읽습니다. 스테레오는 최대 두 채널을 평균내고, 가벼운 1차 필터를 연속 적용해 세 대역을 근사합니다.

- 저역: 약 180Hz 아래의 에너지
- 중역: 저역과 약 2.2kHz 저역 통과 신호의 차이
- 고역: 원 신호와 약 2.2kHz 저역 통과 신호의 차이

각 프레임에서는 대역별 RMS를 계산합니다. FFT보다 계산량이 작아 브라우저에서도 긴 음원을 비교적 빠르게 분석할 수 있습니다.

## 3. 타격 시작점 검출

현재 프레임 에너지가 직전 프레임보다 얼마나 증가했는지 양수 성분만 취합니다. 저역은 킥을 잘 잡도록 `1.45`, 고역은 과도한 하이햇 검출을 줄이도록 `0.38` 가중치를 사용합니다.

최근 약 280ms의 평균 상승량과 전체 분포의 72% 분위수를 함께 사용해 곡의 조용한 부분과 큰 부분을 정규화합니다. 이렇게 만든 `onsetEnvelope`의 지역 최댓값이 타격 후보가 됩니다.

## 4. BPM과 비트 그리드 추정

온셋 엔벨로프를 70~190 BPM 범위의 지연값과 자기상관합니다. 가장 높은 상관을 보이는 지연을 기본 박자로 정하고, 인접 상관값으로 소수 프레임 오차를 보정합니다.

두 배·절반 템포로 잘못 잡히는 현상을 줄이기 위해 최종 BPM은 대체로 78~155 범위로 정규화합니다. 이후 여러 위상 후보를 시험해 온셋 에너지가 가장 많이 겹치는 그리드 시작 위치를 선택합니다.

## 5. 난이도별 노트 선택

타격 후보는 난이도의 그리드 간격 안으로 스냅하고, 한 그리드에 여러 후보가 있으면 가장 강한 하나만 남깁니다.

| 난이도 | 박자 세분화 | 마디당 최대 이벤트 | 선택 분위수 | 동시 노트 |
| --- | ---: | ---: | ---: | ---: |
| CALM | 1 | 3 | 58% | 1 |
| STANDARD | 2 | 6 | 46% | 최대 2 |
| EXPERT | 4 | 12 | 34% | 최대 2 |

분위수 값이 낮을수록 더 약한 타격까지 포함되므로 노트가 많아집니다. 분석 결과가 12개 미만이면 플레이 가능한 리듬을 충분히 찾지 못한 것으로 보고 오류를 반환합니다.

## 6. 4레인 배치

각 이벤트에서 가장 강한 대역을 기본 레인으로 사용합니다.

- 저역 중심 이벤트 → 0번 레인 (`D`)
- 중역 중심 이벤트 → 3번 레인 (`K`)
- 고역 중심 이벤트 → 그리드 순서에 따라 1·2번 레인 (`F`, `J`) 교대

두 번째로 강한 대역이 기본 대역의 70%를 넘고 이벤트 자체도 충분히 강하면 STANDARD와 EXPERT에서 2노트 코드가 될 수 있습니다. 연속된 고역이 같은 손에만 몰리지 않도록 이벤트 순서도 함께 사용합니다.

## 7. 세기와 JSON 생성

선택된 이벤트의 8%~94% 분위수를 `0.35`~`1.0` 범위로 정규화해 `velocity`로 저장합니다. MP3 분석은 음의 지속 시간을 신뢰성 있게 알 수 없으므로 현재는 모두 90ms 탭 노트로 생성합니다.

메타데이터에는 추정 BPM, 곡 길이, 그리드 오프셋, 평균 스냅 오차, 원본 파일명과 분석 방식이 함께 기록됩니다. 이 JSON은 게임 로더와 브라우저의 `JSON 저장` 기능이 사용하는 채보 형식과 같습니다.

## 브라우저와 명령줄 연결 지점

- `src/main.js`: MP3 파일 디코딩, 난이도 선택, 게임과 원곡 재생 연결
- `src/audio-chart-generator.js`: 환경에 독립적인 파형 분석과 채보 생성
- `scripts/audio-file-to-chart.mjs`: FFmpeg PCM 디코딩 어댑터
- `scripts/generate_audio_note_data.mjs`: 완성된 JSON 파일을 저장하는 CLI
- `tests/audio-chart-generator.test.mjs`: 정렬, 4레인 범위, BPM, 난이도별 밀도 검증

## 현재 한계

- 보컬이나 패드처럼 어택이 약한 음원은 이벤트가 적게 검출될 수 있습니다.
- BPM이 크게 변하는 곡은 하나의 전역 BPM만 사용하는 현재 방식과 잘 맞지 않을 수 있습니다.
- MP3 경로는 실제 음정·악기·홀드 길이를 추출하지 않습니다.
- 자동 생성 결과는 초안 채보이므로 음악적 완성도가 필요한 경우 JSON을 후편집하는 편이 좋습니다.
